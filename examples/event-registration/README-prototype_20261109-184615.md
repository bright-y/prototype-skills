# 活动报名原型：运行与维护

修订时间：2026-11-09 18:46:15（Asia/Shanghai）。

总入口：[index.html](index.html)。下载整个仓库并解压后，在浏览器中打开本文件夹的 `index.html`，选择原始版、拆分版或维护版。GitHub 的源码页面不直接运行 HTML；本仓库未启用 GitHub Pages。

## 三个版本

| 目录 | 入口 | 状态 |
| --- | --- | --- |
| `before/` | [index.html](before/index.html) | 一个 HTML，包含内联样式与脚本，姓名和邮箱报名 |
| `after-split/` | [index.html](after-split/index.html) | 提取为 8 个文件，保持同样界面和功能 |
| `after-change/` | [index.html](after-change/index.html) | 8 个文件，增加必填手机号，功能改动仅涉及两个 JS 文件 |

这三个目录是有意保留的案例快照。继续开发时只选定一个版本作为维护来源；当前最终版本为 `after-change/`。它们不需要彼此同步，也不应该把多个版本的脚本同时加载到一个入口。

## 打开方式

使用原生 HTML/CSS/经典 JavaScript 脚本，没有 ES module、`fetch`、CDN、外部字体、图片依赖或软件包。入口通过 hash 路由切换页面，直接打开文件即可操作；未提供独立 HTML 分页，因此不存在片段路径和模块跨源问题。

如需让三个版本共享同一个源，以检查升级后的历史记录，可以在已安装 Python 3 的环境中，自行从本案例目录运行：

```bash
python3 -m http.server 8765 --bind 127.0.0.1
```

再访问 `http://127.0.0.1:8765/`。完成后按 Ctrl+C 停止。该命令仅为可选说明，不是案例运行依赖；请先遵守自己的本地服务授权规则，端口占用时另选端口。

## 文件职责

两个拆分版本的结构相同：

```text
index.html                 # 页面壳、dialog 容器、有序脚本引用
assets/styles.css          # 统一样式和窄屏适配
assets/js/data.js          # 两个虚构活动的数据
assets/js/fields.js        # 字段定义、验证、表单及记录字段的展示
assets/js/store.js         # 存储键、读取、追加和按 ID 防重
assets/js/pages.js         # 活动列表、报名、成功和空状态的页面模板
assets/js/dialog.js        # 确认、取消、Escape、保存失败、提交互斥
assets/js/app.js           # 路由、草稿、一次性事件委托、页面渲染
```

脚本是经典脚本，按入口所列顺序加载，通过 `window.WeekendDemo` 共享小型命名空间。不能随意调整顺序或把一个脚本改成 module。页面导航只替换 `main` 内容；全局和弹窗监听器仅在启动时绑定一次，没有轮询计时器。

## 数据与错误处理

- 仅使用 localStorage 键 `prototype-skills:event-registration:v1`，不调用后端。
- 不自动创建、删除或迁移报名记录。保存采用追加，保留旧记录及其未知字段。
- 新版允许读取没有手机号的历史记录，在详情中标明“未填写（旧记录）”；只有新报名必须填写手机号。
- 确认弹窗取消或按 Escape 不保存。相同 ID 的保存不重复追加。
- 读取损坏数据或保存失败时显示错误，不清空已有数据，不跳转为成功。
- 手机号仅检查中国大陆 11 位格式，不验证号码归属或可达性。请使用演示信息，不填写真实个人信息。
- 浏览器可能将 `file://` 存储按文件隔离，也可能限制文件模式的存储。三个快照不保证自动共享记录；跨版本验证应使用同一个 HTTP 源，或使用测试中的内存存储夹具。
